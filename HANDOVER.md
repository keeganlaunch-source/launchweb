## Step-by-step (about 15 minutes)

### 1. Link this folder to the Vercel project
```bash
unzip launch-lifestyle-handover.zip && cd launch-lifestyle
npm install
npx vercel login              # Keegan's account
npx vercel link               # choose the existing project: launch-lifestyle
```

### 2. Database
Pick one:

**A. New Neon database (recommended, clean and owned by Keegan).**
In Vercel: project > Storage > Create Database > Neon > free plan > Connect to
project (all environments). Vercel sets `DATABASE_URL` automatically. Then load the data:
```bash
npx vercel env pull .env.local
export $(grep '^DATABASE_URL=' .env.local)
npm run db:restore            # loads data/db-backup.sql
```

**B. Reuse the Neon database the Replit app already used.** Its URL is in
`secrets/vercel.env` (commented out). It has the same tables. Before choosing it,
confirm its row counts match the dump (27 newsletter_signups, 26 pdf_purchases,
6 contact_messages, 3 pdf_products, 10 consultation_draw, ~8100 analytics). If they
match, uncomment `DATABASE_URL` in `secrets/vercel.env` and skip the restore.

### 3. Environment variables
```bash
bash scripts/push-env-to-vercel.sh secrets/vercel.env
```
This pushes every key to production and preview. `DISABLE_ALL_EMAILS` is `true` so no
customer receives a stray email while testing.

### 4. Deploy and test
```bash
npx vercel --prod
```
Check:
- home page loads and images show
- `/api/next-email-schedule` returns JSON
- Launch AI chat answers a question
- `/analytics-hub` loads (password is in the source, see Security)
- a Paystack test purchase of the recipe book completes (LIVE keys: refund it after)

### 5. Turn emails on
In Vercel > Settings > Environment Variables set `DISABLE_ALL_EMAILS` to `false`, redeploy.
The Mon/Wed/Fri emails and the Monday report now run from Vercel Cron
(see `vercel.json`); Vercel sends `CRON_SECRET` automatically.

### 6. Domain (last)
Vercel > Settings > Domains > add `launchfit.app` and `www.launchfit.app`. Update DNS at
the registrar as Vercel shows (A 76.76.21.21 for apex, CNAME cname.vercel-dns.com for www).
Then update webhook/redirect URLs that still point at Replit, if any: Paystack webhook,
Sudor webhook (`/api/webhooks/sudor`), Google OAuth redirect (`/api/oauth2callback`).
Finally cancel the Replit deployment and subscription.

### 7. Clean up
```bash
rm -rf secrets .env.local
```
The values now live in Vercel. Do not commit them.


## What changed from the Replit version
- `vite.config.ts`: Replit-only plugins removed.
- `server/db.ts`: Neon driver for Neon URLs, plain `pg` for any other Postgres.
- `server/index.ts` split into `server/app.ts` (app factory) + `server/index.ts` (listener).
- `server/cron.ts` + `vercel.json` crons replace node-cron on Vercel.
- `api/index.js` loads a prebundled `api/_app.mjs` (generated by `npm run build`).
- `server/email-notifications.ts`: `REPLIT_DEV_DOMAIN` replaced by `PUBLIC_BASE_URL`.
- Firebase/Google Analytics credentials read from env instead of a hard-coded file.
- The error middleware no longer re-throws (that crashed the process on Replit).
- `attached_assets/` trimmed to the 10 images the code imports (was 840 MB of chat uploads).

## Known limits on Vercel
- Sessions are in-memory, so they last one invocation. Only the YouTube OAuth flow uses
  them. Switch to `connect-pg-simple` (already installed) if that matters.
- Launch AI "conversation memory" resets per invocation. Chat still works.
- The integration monitor and weekly-report `setInterval` loops do not run; the cron
  endpoints cover the scheduled emails.
